# Counie CS 운영 인텔리전스

SQL 기반 운영 KPI 모니터링과 정책 근거형 AI 상담 지원 자동화를 설계한 재현 가능한 포트폴리오 프로젝트입니다. 인하우스 상담 인력의 업무량과 문의 흐름을 분석하고, SLA 위험·문의 급증·고위험 티켓을 식별해 운영 리더의 판단을 돕는 것을 목표로 합니다.

> 모든 티켓·상담사·정책 데이터는 포트폴리오 목적의 결정론적 가상 데이터입니다. 생성된 결과는 실제 고객, 상담사 성과 또는 사업 성과를 의미하지 않습니다.

[포트폴리오 케이스 스터디](docs/portfolio_case_study.md)

## 문제와 설계

| 운영 질문 | 구현 |
| --- | --- |
| 어느 문의 유형·시간대가 SLA 위험을 만드는가? | 일별/유형별 KPI, 미처리 티켓 위험 점수, 이상 징후 탐지 |
| 어떤 티켓을 자동화하면 안 되는가? | PII 마스킹, 고위험 키워드·재문의·SLA 기반 검수 라우팅 |
| 답변 초안이 어떤 정책을 근거로 하는가? | 유효 기간과 버전 메타데이터를 가진 정책 검색·출처 표시 |
| AI 지원이 실제 운영에 유용한가? | 승인·수정·반려율, 처리시간, 보류 적절성, 티켓당 비용 측정 설계 |

```text
상담 이력 · 배정 데이터 · 문의 티켓 · 정책 문서 · 이벤트 로그
  → 품질 검사/PII 마스킹 → KPI·이상 징후 분석 → 정책 검색·답변 초안
  → 위험도 기반 상담사 검수/전문팀 라우팅 → 리포트·평가 피드백
```

## 실행

Python 3.10 이상과 외부 패키지 없이 실행됩니다.

```bash
python data/generate_synthetic_data.py
python src/operations_pipeline.py
python -m unittest discover -s tests -v
```

생성 결과:

- `outputs/operations_summary.json`: KPI, SLA 위험, 이상 징후, 검수 라우팅 요약
- `outputs/review_queue.csv`: 전문 상담사 검수가 필요한 티켓 큐
- `outputs/daily_report.md`: 운영 리더용 일일 리포트
- `outputs/ai_assist_audit.csv`: 정책 근거·위험도·라우팅을 포함한 감사 로그

## 범위와 한계

- 기본 실행은 재현성을 위해 로컬 규칙 기반 분류·요약을 사용함.
- `OPENAI_API_KEY` 환경 변수와 `--use-openai` 옵션으로 구조화된 JSON 분류를 선택할 수 있으나, API 키나 실제 고객 데이터는 저장소에 포함하지 않음.
- 실제 도입 전에는 정책 최신성, 개인정보 처리 근거, 모델 공급사 보안 검토, 상담 품질, 고객 만족도, 비용 및 SLA 영향을 별도로 검증해야 함.
