# Sales & Marketing Analytics + AI Copilot

영업·마케팅 데이터의 단절을 데이터 마트와 의사결정 화면으로 해소하고, 그 데이터를 안전한 AI 업무 보조 도구의 근거로 활용하는 **가상 케이스 스터디**입니다.

[English version](README.en.md)

> **범위 고지:** 이 문서는 포트폴리오 목적의 가상 사례입니다. 회사·고객·데이터·성과 수치는 실제 사례가 아니며, 실제 서비스 운영 성과나 특정 기업의 시스템을 의미하지 않습니다.

## Problem

CRM, 광고 매체, 웹 행동, 영업 기회, 매출 데이터가 분리되어 있으면 채널별 리드 수는 확인할 수 있어도, 어느 고객군·캠페인에 영업과 마케팅 자원을 우선 배분해야 하는지 일관되게 판단하기 어렵습니다. 영업 담당자는 여러 도구를 오가며 리드를 조사하고 다음 행동을 정해야 합니다.

## Approach

### 1. Decision-ready data mart

고객과 리드를 공통 식별자로 연결하고, 아래의 분석용 모델을 설계합니다.

| Model | Purpose |
| --- | --- |
| Customer / lead | 고객 세그먼트, 유입 채널, 담당자, 상태를 일관된 형태로 제공 |
| Touchpoint | 가격 페이지, 데모 신청, 콘텐츠 반응 등 구매 의도 신호를 기록 |
| Opportunity / revenue | 영업 단계, 예상 가치, 순매출을 채널·캠페인과 연결 |
| Daily growth mart | 리드, MQL, SQL, 기회, 매출을 일자·채널·캠페인 단위로 집계 |
| Lead-priority mart | 적합도, 구매 의도, 최근 활동, 예상 가치를 설명 가능한 점수로 결합 |

데이터 품질은 기본 키 고유성, 필수 필드, 허용 상태값, 리드와 접점·기회의 참조 무결성으로 검증합니다.

### 2. Decision workflow

- **Growth Command Center:** 목표 대비, CAC, 파이프라인, 주요 변화 확인
- **Funnel & Response SLA:** 단계별 전환, 리드 적체, 고가치 리드의 최초 응답 시간 확인
- **Channel-to-Revenue:** 리드 수가 아니라 SQL·기회·순매출 기준으로 채널과 캠페인을 비교
- **Lead queue:** 설명 가능한 우선순위 점수로 오늘 검토할 리드를 제안

### 3. AI Sales Copilot boundary

Copilot은 승인된 데이터 마트의 읽기 전용 컨텍스트에서 담당 리드의 근거와 다음 행동 초안을 짧게 정리합니다. 점수 계산은 규칙 기반 모델이 담당하며, LLM은 사실을 새로 만들지 않고 근거를 요약합니다.

- 요청자 권한에 맞는 행만 조회
- 추천에 출처, 데이터 갱신 시각, 미확인 정보를 포함
- CRM 기록 변경이나 고객 연락은 사람의 확인 없이는 실행하지 않음
- 근거 정확도, 유용성, 추천 채택률, 권한 위반을 별도 측정

## Validation scope

실제 성과를 주장하지 않습니다. 실제 도입 시에는 도입 전후와 비교군을 기준으로 리서치 시간, 고가치 리드의 최초 접촉 시간, 추천 채택률, MQL→SQL 전환율을 검증합니다. 채널 믹스, 계절성, 영업 인력 변화도 함께 통제합니다.

## Technical evidence

공개 가능한 구현 저장소에는 합성 데이터, dbt SQL 모델, 데이터 테스트, 로컬 실행 방법, Copilot의 권한·감사·확인 단계 설계를 포함할 예정입니다. 원천 고객 데이터, 비공개 키, 실제 성과 데이터는 공개하지 않습니다.

## Skills demonstrated

- 비즈니스 병목을 지표·데이터 모델·업무 흐름으로 번역
- SQL 기반 데이터 마트와 데이터 품질 규칙 설계
- 분석 결과를 예산·리드 배정·영업 활동이라는 액션으로 연결
- AI 업무 보조 기능을 권한·근거·사람 확인을 포함한 운영 도구로 설계
