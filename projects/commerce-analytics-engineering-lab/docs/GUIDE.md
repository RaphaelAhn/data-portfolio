# 설명서 (누구나 따라 할 수 있는 안내서)

> 이 문서는 데이터 엔지니어링을 잘 모르는 사람도 "이게 뭐 하는 프로젝트인지", "내 컴퓨터에서 어떻게 실행하는지"를 그대로 따라 할 수 있도록 쉬운 말로 씁니다. 설계 이유가 궁금하면 [기획서](PLAN.md), 코드 구조가 궁금하면 [기술서](TECHNICAL_GUIDE.md)를 보세요.

## 한 줄 요약

주문·결제·환불·재고처럼 여러 곳에 흩어진 쇼핑몰 데이터를, "오늘 매출이 얼마였는지" 하나의 정확한 숫자로 만들어주는 프로그램입니다.

## 왜 필요한지 (비유로 설명)

집안 살림에 비유하면 이렇습니다.

- 장바구니 영수증(주문)
- 카드 결제 문자(결제)
- 환불 내역서(환불)
- 냉장고 재고 목록(재고)

이 네 가지 종이를 각자 다른 서랍에 넣어두면, "이번 달에 얼마 썼지?"를 알려면 서랍 네 개를 다 뒤져서 손으로 계산해야 합니다. 이 프로젝트는 그 서랍 네 개를 자동으로 열어서, 계산 규칙(예: "환불된 건 빼고 계산")을 정해놓고 항상 같은 방식으로 정리해주는 자동 정리함입니다.

## 전체 흐름 그림

```text
[원본 데이터 7개 CSV 파일]
   주문 / 주문상품 / 결제 / 환불 / 상품 / 고객 / 재고이벤트
          │
          ▼
[1단계: 정리하기 - staging]
   글자를 숫자로 바꾸고, 중복을 지우고, 최신 기록만 남김
          │
          ▼
[2단계: 계산하기 - intermediate]
   주문 금액 계산, 결제와 환불을 맞춰보기, 재고 늘고 줄어든 것 계산
          │
          ▼
[3단계: 완성하기 - marts]
   "오늘 매출이 얼마인지" 같은 최종 결과표 완성
```

## 설치부터 실행까지 따라 하기

**준비물**: Windows PC, Python 3.11 이상

**1단계. 이 프로젝트 폴더로 이동**

```bash
cd Git_portfolio/data-portfolio/projects/commerce-analytics-engineering-lab
```

**2단계. 가상환경 만들기 (내 컴퓨터의 다른 프로그램과 섞이지 않게 하는 격리 공간)**

```powershell
python -m venv .venv
```

**3단계. 필요한 프로그램 설치**

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**4단계. 파이프라인을 두 번 실행해서 결과가 똑같은지 자동으로 확인**

```powershell
.\.venv\Scripts\python.exe scripts\verify_idempotency.py
```

이 명령어 하나가 하는 일:
1. 7개의 CSV 파일을 데이터베이스에 넣습니다.
2. dbt가 정리 → 계산 → 완성 3단계를 순서대로 실행합니다.
3. 같은 과정을 한 번 더 반복합니다.
4. 두 번의 결과가 정확히 같은지(SHA-256이라는 지문 비교 방식으로) 확인합니다.

**마지막에 보이는 문장으로 결과 확인**

- `PASS=71` 같은 문구가 보이면 성공입니다. (숫자 71은 seed 7개 + model 17개 + test 47개를 합친 개수)
- `ERROR`가 하나라도 보이면 무언가 잘못된 것입니다.

## 결과물은 어디서 확인하나요

- `mart_daily_commerce_kpi`: 날짜별로 "완료된 주문 수 / 매출 / 평균 주문 금액"이 정리된 표
- `mart_inventory_health`: 상품별로 "지금 재고가 몇 개 남았는지 / 품절 위험인지"가 정리된 표

이 표들은 DuckDB(가벼운 로컬 데이터베이스) 안에 만들어지며, DB 브라우저 프로그램이나 Python으로 열어서 확인할 수 있습니다.

## 자주 묻는 질문 (FAQ)

**Q. 실제 쇼핑몰 데이터를 쓰나요?**
아니요. 실제 회사나 고객 데이터를 전혀 쓰지 않고, 미리 정해둔 가상의 예시 데이터(seed)만 사용합니다.

**Q. 왜 같은 파일을 두 번 돌려보나요?**
현실에서는 같은 주문 파일이 실수로 중복 실행되는 사고가 자주 일어납니다. 두 번 돌려도 매출이 두 배로 부풀지 않는다는 것을 직접 보여주기 위해서입니다.

**Q. "늦게 도착한 환불"이 뭔가요?**
예를 들어 8월 10일에 있었던 주문의 환불이 8월 12일에야 시스템에 기록되는 경우입니다. 이럴 때 이 프로젝트는 8월 10일 매출을 8월 12일 시점에 자동으로 다시 계산해서 정확하게 고쳐줍니다.

## 문제가 생겼을 때 체크리스트

1. `python` 명령어가 안 먹히나요? → Python이 설치돼 있는지, PATH에 등록돼 있는지 확인
2. `pip install` 중 오류가 나나요? → 인터넷 연결 확인, `requirements.txt` 파일이 폴더 안에 있는지 확인
3. `ERROR`가 뜨나요? → 로그 메시지에 표시된 모델 이름을 보고 `models/` 폴더에서 같은 이름의 `.sql` 파일을 확인
4. 그래도 모르겠다면? → [기술서](TECHNICAL_GUIDE.md)의 "레이어별 책임" 섹션에서 어느 단계 문제인지 먼저 좁혀보세요
